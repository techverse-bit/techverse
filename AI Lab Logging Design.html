AI Lab logging design

For every call to the lab we record each step it goes through: how long it took and whether it passed. Everything is collected in Elasticsearch and viewed in Kibana, where alerts warn us before small problems become big ones.

12steps recorded per call
1 idto follow a call end to end
2 levelsof alerts: warning, critical
0questions, answers or keys stored

01How it works

In short

  • Each call gets a request id at the front door.
  • Every step writes one line: the step, the time it took, and the result.
  • At the end, one summary line shows where all the time went.
  • Kibana shows it all and sends alerts when something crosses a limit.

Tools

  • Nginx: the front door; creates the request id and records calls even if the app is down.
  • Filebeat, Metricbeat, Heartbeat: small Elastic helpers on each Mac that send logs, health readings and alive checks.
  • Elasticsearch: stores and searches everything.
  • Kibana: search, dashboards and alerts.

02What we record for every call

Every call passes these 12 steps. Each step is recorded with its time and result.

StepWhat we record
C1 Front doorCall arrived, from which IP, final status. Also catches calls the app never answered.
C2 Key and slot checkValid key? Inside the booked slot? User active? Which booking.
C3 LimitsToken limit reached.
C4 Personal data checkWhat type was found (e.g. email, Aadhaar) and what was done: allowed, masked or blocked.
C5 Secrets checkPassword or key found? Blocked or not.
C6 Safety check on questionQwen3Guard verdict: safe, harmful or a prompt trick.
C7 Model chosenWhich model, which Mac, and how busy each Mac was.
C8 WaitingHow long the call waited before the model started working on it, and how many other calls that model was handling at that moment. Shows when a model is overloaded.
C9 AnswerTime to the first word, total time, words (tokens) in and out, speed.
C10 Safety check on answerQwen3Guard verdict on the answer; whether it was cut off.
C11 SavedThe masked question and answer saved to the chat history (kept 7 days) and the safety check results saved to the database, or the error if saving failed.
C12 FinishedOne summary line. The gateway notes each step's time as the call goes; when the answer has fully gone back, it writes all of them as one line, with the total and the result.

04Finding a slow or failed call

1 · Find the call

Search its request id in Kibana, or pick one from the slowest calls on the dashboard.

2 · Read the summary

The biggest number shows which step caused the delay or failure.

3 · Check the likely cause:

Biggest stepLikely causeLook at
WaitingToo many people on that model at onceHow busy each Mac was; was work shared evenly?
Answer, but it was longNormal: a long answer takes longerNothing to fix
Answer, and it was slow per wordThe Mac is strugglingThat Mac's temperature and memory at that minute
Safety checksQwen3Guard, Presidio or Gitleaks is slowThat checker's up-check and its Mac's load
Key check or savingThe database is slowThe database's slow-query log
Not in any stepTime lost between machinesNetwork and the Mac mini's CPU

To confirm: answers are streamed word by word, and Qwen3Guard checks them in pieces as they come. This keeps the first word under the 5-second SLA. If a piece is unsafe, the answer is cut off at that point.

06Alerts

So alerts stay useful

  • Sent once, followed by a "back to normal" message, never repeated every minute.
  • Limits are starting values; we review them after two weeks of real use.
  • Each alert links to the dashboard that explains it.

One thing to check

Kibana can send email and Teams alerts only with an Elastic Gold licence or higher. If the bank has the free licence, a small script on the Mac mini sends them instead.

07Rules we follow

Nothing sensitive

Never log questions, answers, files, API keys or passwords, and only the employee id, never names or emails. Elasticsearch also removes anything like that on arrival, as a second check.

One id per call

Every line of a call carries the same request id, so one search shows the whole story. Users see the id too and can quote it.

Same clock everywhere

All three Macs take their time from the bank's time server, so steps line up across machines.

Logging never slows the lab

Lines go to a local file first, in the background. If logging fails, the lab keeps working.

Same names for everyone

One shared list of event names, so searches and dashboards keep working as the code grows.

Audit logs are evidence

Kept for the bank's required time; nobody can edit or delete them, not even lab admins.
