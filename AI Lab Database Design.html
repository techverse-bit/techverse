AI Lab database design

The tables the API-based AI Lab needs, how they relate, how long each piece of data is kept and how big it gets. Users request a 2-hour slot in the portal (up to 40 people per slot); an admin approves it, and the booking then gets its own API key that works only during that slot. Covers people, sign-ins, slots, bookings and keys, hardware, chats, usage and guard blocks. Sized for 200 employees, about 120 active a day and 3,000 requests a day, on the Mac mini's PostgreSQL.

03Chats in PostgreSQL: how JSON is stored

No separate NoSQL database is needed. PostgreSQL's jsonb type stores JSON documents natively, compressed and indexable, inside normal tables.

How it is stored

  • Structured columns for what we search and secure by: conversation, owner, order, role, time.
  • One jsonb column (messages.content) for the flexible message body: text parts, file references, tool calls.
  • One row per message, appended as the conversation grows. Not one big JSON document per conversation, which would be rewritten on every reply.
  • Only the new turns of each API call are saved. The client resends the earlier history every time, so storing it again would multiply the size.
  • Redacted text only. Presidio masks personal data before saving; blocked prompts are not saved at all; guard_blocks records only the stage and reason.

Why not MongoDB or another NoSQL store

  • JSONB already gives document storage, with indexing and JSON queries.
  • One database to run, secure and back up on the 24GB Mac mini.
  • Chats join directly to users, so row-level security keeps each person's chats private.
  • Transactions: a message and its request record are saved together or not at all.
  • The 7-day deletion is one SQL statement.

07Key check and scheduled jobs

How the gateway decides whether a key may be used right now:

-- Run by the gateway on every API call (result cached for a few seconds)
-- $1 = the key the caller sent (text). No row returned = call refused.
SELECT b.employee_id
FROM bookings b
JOIN slots s ON s.starts_at   = b.slot_start
JOIN users u ON u.employee_id = b.employee_id
WHERE b.key_hash = sha256(convert_to($1, 'UTF8'))
  AND b.status   = 'approved'
  AND u.status   = 'active'                          -- suspended users are refused
  AND now() >= s.starts_at AND now() < s.ends_at;   -- only inside the booked slot

Jobs run inside PostgreSQL with pg_cron:

-- 02:00  Delete chats inactive for 7 days (messages and attachment rows follow by cascade)
SELECT cron.schedule('purge-chats', '0 2 * * *', $$
  DELETE FROM conversations WHERE last_activity_at < now() - interval '7 days';
$$);

-- 02:30  Remove year-old usage records (guard blocks follow by cascade), logins, bookings (with their keys) and slots
SELECT cron.schedule('purge-old', '30 2 * * *', $$
  DELETE FROM requests WHERE received_at < now() - interval '1 year';
  DELETE FROM logins   WHERE logged_in_at < now() - interval '1 year';
  DELETE FROM bookings WHERE slot_start < now() - interval '1 year';
  DELETE FROM slots    WHERE starts_at  < now() - interval '1 year';
$$);

-- Sunday 01:00  Create next week's slots: Mon–Fri, five 2-hour slots from 09:00 to 19:00 IST, 40 places each
-- (database time zone set to Asia/Kolkata)
SELECT cron.schedule('create-slots', '0 1 * * 0', $$
  INSERT INTO slots (starts_at, ends_at, capacity)
  SELECT d + h * interval '1 hour', d + (h + 2) * interval '1 hour', 40
  FROM generate_series(date_trunc('week', now()) + interval '7 days',
                       date_trunc('week', now()) + interval '11 days', interval '1 day') AS d,
       unnest(ARRAY[9, 11, 13, 15, 17]) AS h
  ON CONFLICT (starts_at) DO NOTHING;
$$);
-- 02:45  The portal's file job deletes any file on disk whose attachments row no longer exists.

08Security

Access

  • Row-level security on conversations, messages, attachments, requests and bookings: members see only their own rows; admins see all. logins and guard_blocks are admin-only.
  • No passwords in the database: sign-in is Keycloak with Active Directory; users keeps only the staff id, team and location, not names or emails.
  • API keys stored as SHA-256 hashes; the key is shown once and works only during its booked slot.
  • Separate database roles for the portal, the gateway and Grafana (read-only: requests, guard_blocks, logins).

Protection

  • Encrypted at rest (FileVault on the Mac mini, encrypted backup SSD) and in transit (TLS).
  • Redacted text only, deleted after 7 days.
  • Nightly backup with pg_dump; restore tested quarterly.
  • Official audit copy of sign-ins, admin actions and guard blocks in Elasticsearch, outside the database admins' reach.

CREATE EXTENSION IF NOT EXISTS pg_cron;      -- nightly clean-up

CREATE TYPE user_role      AS ENUM ('member','admin');
CREATE TYPE user_status    AS ENUM ('active','suspended');
CREATE TYPE login_result   AS ENUM ('success','failed');
CREATE TYPE booking_status AS ENUM ('pending','approved','rejected','cancelled');
CREATE TYPE node_status    AS ENUM ('online','maintenance','offline');
CREATE TYPE model_role     AS ENUM ('reasoning','fast','guard');
CREATE TYPE deploy_status  AS ENUM ('active','disabled');
CREATE TYPE msg_role       AS ENUM ('system','user','assistant','tool');
CREATE TYPE req_status     AS ENUM ('ok','error','blocked','withheld');
CREATE TYPE guard_stage    AS ENUM ('question','answer');
CREATE TYPE block_reason   AS ENUM ('pii','secret','harmful','injection');

-- People ---------------------------------------------------------------
CREATE TABLE departments (
  name              text PRIMARY KEY,
  daily_token_limit int  NOT NULL DEFAULT 200000 CHECK (daily_token_limit >= 0)
);

CREATE TABLE locations (
  code text PRIMARY KEY,                                     -- e.g. BLR-GBS
  name text NOT NULL,
  city text NOT NULL
);

CREATE TABLE users (
  employee_id text PRIMARY KEY,                              -- bank staff number
  department  text NOT NULL REFERENCES departments(name) ON UPDATE CASCADE,
  location    text NOT NULL REFERENCES locations(code)   ON UPDATE CASCADE,
  role        user_role   NOT NULL DEFAULT 'member',
  status      user_status NOT NULL DEFAULT 'active',
  created_at  timestamptz NOT NULL DEFAULT now()
);
-- Foreign keys to users use ON UPDATE CASCADE so the staff id can be anonymised later.

CREATE TABLE logins (
  employee_id  text NOT NULL REFERENCES users ON UPDATE CASCADE,
  logged_in_at timestamptz NOT NULL DEFAULT now(),
  ip_address   inet NOT NULL,
  result       login_result NOT NULL,
  PRIMARY KEY (employee_id, logged_in_at)
);
CREATE INDEX ON logins (logged_in_at);

-- Bookings and keys -----------------------------------------------------
CREATE TABLE slots (
  starts_at timestamptz PRIMARY KEY,
  ends_at   timestamptz NOT NULL CHECK (ends_at > starts_at),
  capacity  smallint NOT NULL DEFAULT 40 CHECK (capacity > 0)
);

CREATE TABLE bookings (
  employee_id text NOT NULL REFERENCES users ON UPDATE CASCADE,
  slot_start  timestamptz NOT NULL REFERENCES slots,
  status      booking_status NOT NULL DEFAULT 'pending',     -- admin approves or rejects
  key_prefix  text  UNIQUE CHECK (length(key_prefix) = 8),   -- null until approved
  key_hash    bytea UNIQUE,                                  -- SHA-256, key never stored
  created_at  timestamptz NOT NULL DEFAULT now(),
  PRIMARY KEY (employee_id, slot_start),                     -- one booking per person per slot
  CHECK (status <> 'approved' OR key_hash IS NOT NULL)       -- an approved booking always has a key
);
CREATE INDEX ON bookings (slot_start) WHERE status = 'approved';
CREATE INDEX ON bookings (created_at) WHERE status = 'pending';  -- admin's approval queue

-- Refuse an approval when the slot already has 40 approved bookings
CREATE FUNCTION check_slot_capacity() RETURNS trigger LANGUAGE plpgsql AS $$
DECLARE cap smallint;
BEGIN
  SELECT capacity INTO cap FROM slots WHERE starts_at = NEW.slot_start FOR UPDATE;  -- one approval at a time
  IF (SELECT count(*) FROM bookings
       WHERE slot_start = NEW.slot_start AND status = 'approved'
         AND employee_id <> NEW.employee_id) >= cap THEN
    RAISE EXCEPTION 'slot % is full', NEW.slot_start;
  END IF;
  RETURN NEW;
END $$;
CREATE TRIGGER slot_capacity BEFORE INSERT OR UPDATE OF status ON bookings
  FOR EACH ROW WHEN (NEW.status = 'approved') EXECUTE FUNCTION check_slot_capacity();
-- On approval the portal generates the key, stores its prefix and hash here, and shows it to the user once.

-- Usage and safety ------------------------------------------------------
CREATE TABLE requests (
  id                uuid PRIMARY KEY,                        -- also written to the logs
  employee_id       text NOT NULL REFERENCES users ON UPDATE CASCADE,
  node              text,                                    -- NULL if blocked before routing
  model             text,
  received_at       timestamptz NOT NULL DEFAULT now(),
  ttft_ms           int,
  latency_ms        int,
  prompt_tokens     int NOT NULL DEFAULT 0,
  completion_tokens int NOT NULL DEFAULT 0,
  status            req_status NOT NULL,
  FOREIGN KEY (node, model) REFERENCES deployments,
  CHECK ((node IS NULL) = (model IS NULL))                   -- both set, or both empty
);
CREATE INDEX ON requests (received_at);
CREATE INDEX ON requests (employee_id, received_at);

CREATE TABLE guard_blocks (
  request_id uuid PRIMARY KEY REFERENCES requests ON DELETE CASCADE,
  stage      guard_stage  NOT NULL,
  reason     block_reason NOT NULL                          -- blocked text is never stored
);

-- Chats (7 days) ----------------------------------------------------------
CREATE TABLE conversations (
  id               uuid PRIMARY KEY,                         -- sent by the API client
  employee_id      text NOT NULL REFERENCES users ON UPDATE CASCADE,
  last_activity_at timestamptz NOT NULL DEFAULT now()
);
CREATE INDEX ON conversations (employee_id, last_activity_at DESC);
CREATE INDEX ON conversations (last_activity_at);

CREATE TABLE messages (
  id              bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  conversation_id uuid NOT NULL REFERENCES conversations ON DELETE CASCADE,
  role            msg_role NOT NULL,
  content         jsonb NOT NULL,                            -- redacted body only
  request_id      uuid REFERENCES requests ON DELETE SET NULL,
  created_at      timestamptz NOT NULL DEFAULT now()
);
CREATE INDEX ON messages (conversation_id, id);

CREATE TABLE attachments (
  storage_path text PRIMARY KEY,
  message_id   bigint NOT NULL REFERENCES messages ON DELETE CASCADE,
  file_name    text NOT NULL,
  mime_type    text NOT NULL,
  size_bytes   int  NOT NULL CHECK (size_bytes <= 25 * 1024 * 1024),
  created_at   timestamptz NOT NULL DEFAULT now()
);
CREATE INDEX ON attachments (message_id);

-- Members see only their own rows. The portal sets app.employee_id and app.role for each session.
-- Same pattern on requests and bookings; messages and attachments follow their conversation.
ALTER TABLE conversations ENABLE ROW LEVEL SECURITY;
CREATE POLICY own_rows ON conversations
  USING (employee_id = current_setting('app.employee_id', true)
         OR current_setting('app.role', true) = 'admin');

ALTER TABLE messages ENABLE ROW LEVEL SECURITY;
CREATE POLICY own_rows ON messages               -- visible only if its conversation is visible
  USING (EXISTS (SELECT 1 FROM conversations c WHERE c.id = conversation_id));
