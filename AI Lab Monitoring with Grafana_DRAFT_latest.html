AI Lab monitoring with Grafana

How we will watch the AI Lab: what is measured, where the data comes from, where it is stored, where audit records live, what the dashboards look like and how to set it all up. Everything runs inside the lab on free, open-source tools.

01In one minute

Like a hospital patient monitor: sensors measure, a recorder keeps the readings, a screen shows them and an alarm sounds when something is wrong.

Measure

Helpers on each Mac

Small programs read CPU, memory, disk, GPU, temperature and model heartbeats. The gateway, portal and guardrails report speed, users and safety events.

Store

Prometheus + Elasticsearch

Prometheus keeps the numbers over time. Elasticsearch keeps the events and audit records, searchable. Both live on the Mac mini.

Show

Grafana dashboards

Grafana reads both stores and draws live dashboards in a browser. It stores nothing itself and never sees what users type.

Alert

Heartbeat emails

Grafana checks the numbers all the time and emails the lab team when one crosses a limit, so nobody has to keep watching.

02Architecture

Monitoring runs entirely on the Mac mini. The Mac Studios only report to it over the lab switch, and the lab team opens Grafana through the same HTTPS address as the portal, so no new firewall port is needed.

Solid lines carry numbers or events into the stores; the dashed line carries model server logs. The only new network rule is the one already in the proposal: the Mac mini to the bank mail relay, for alert emails.

How audit records are handled

  • Read-only; access limited to the lab owner and backup, reviewed monthly
  • Searched on the Audit dashboard, or in Grafana Explore (for example, every failed sign-in this week)
  • Exported to internal audit on request
  • Optional: copied to the bank's central log system if InfoSec requires (one extra firewall rule)
  • Never stored: prompt or response text

07How we configure it

Done once the Macs arrive. About a week for someone new to Grafana, mostly building and tuning panels.

  1. Bring in the software

    InfoSec approves and imports Grafana, Prometheus, Elasticsearch, Node Exporter and macmon through the approved route, since the lab has no internet. All are free and open source.

  2. Start the helpers

    Node Exporter on all three Macs. macmon on both Mac Studios, on port 9091 so it does not clash with Prometheus.

  3. Point Prometheus at the helpers

    One file on the Mac mini lists every helper to read: Node Exporter on all three Macs, macmon on both Mac Studios and LiteLLM.

  4. Turn on LiteLLM metrics

    One setting in LiteLLM's configuration. Confirm it is included in the free version; if not, Grafana reads the same numbers from LiteLLM's own database.

  5. Send events to Elasticsearch

    The portal (sign-ins, sessions, admin changes), the guardrails (blocked prompts) and the model servers (load failures) write their events through a log shipper such as Filebeat, or the bank's standard one.

  6. Connect Grafana to both stores

    In Grafana: Connections → Data sources → add Prometheus and Elasticsearch. Then build the six dashboards panel by panel: each panel is a chart type plus a query.

  7. Set up alerts and email

    Create the six alert rules and a contact point for the lab team's email, sent through the bank mail relay.

  8. Sign-in and roles

    Turn on Active Directory sign-in (Grafana's LDAP setting). Lab team: Viewer. Lab owner and backup: Admin. Serve Grafana at /grafana behind the portal's HTTPS address.

  9. Save it as code

    Export every dashboard and alert rule as a file into the internal git repository. Grafana loads them from files at start-up, so the setup can be rebuilt or rolled back in minutes.
